Raspberry Pi Bench Instrument

A four-mode bench instrument: function generator, voltmeter, ohmmeter and DC reference, driven by a rotary encoder and a 20×4 LCD. I was project lead and electrical lead on a team of five, and designed the analog side.

ConstraintNo instrumentation ICs.

The rule that made this project worth doing was that we could not buy the measurement. No ADC chip, no dedicated ohmmeter front end. If the instrument needed to measure a voltage, we had to build the circuit that measures voltage.

That converts a software exercise into an analog design problem. A Raspberry Pi has no analog input at all, so the voltmeter cannot be a library call. It has to be designed.

I ran the project and owned the analog side. What follows is the portion I designed.

VoltmeterA successive-approximation ADC built from discrete parts.

The voltmeter is a 6-bit successive-approximation ADC constructed from an R-2R ladder and a comparator.

An R-2R ladder DAC across six GPIO pins generates a trial voltage. A comparator compares that trial against the unknown input and returns a single bit. The Pi walks from the most significant bit down, retaining each bit that does not overshoot. Six comparisons produce six bits: a binary search executed in hardware.

This is the item I would want to be questioned on. The default move is to specify an ADS1115 and move on. Building the converter forces you to understand what an ADC actually is: the ladder's output impedance, the comparator's offset and propagation delay, the settling time you must allow between trials, and why six bits was the honest resolution limit rather than an arbitrary choice. There is no datasheet doing that reasoning for you.

OhmmeterA divider swept until the comparator trips.

The unknown resistor forms the top leg of a voltage divider. The bottom leg is an MCP4231 digital potentiometer in series with a fixed resistor. The Pi sweeps the digipot across its 128 steps while watching a comparator; the step at which the divider midpoint crosses the threshold determines the unknown value.

The design work is in the fixed series resistor, because it sets where the measurable window lands. I started at 324Ω and moved to 422Ω to centre the range, which placed the floor near 526Ω and the ceiling near 9.8kΩ. That covers the 500Ω to 10kΩ target properly rather than wasting half the digipot's travel below the range of interest.

Push-pull output stageDriving a load from a single supply.

The output stage is a Class AB push-pull amplifier: a TL071CP op-amp driving complementary MOSFETs, an IRFZ24N sourcing current and an IRF5210 sinking it.

Only a single 24V rail was available, so I split it into ±12V using a resistor divider with Zener clamps and a bypass capacitor to establish a stable virtual ground. It is not as clean as a true dual supply, but the Zener and capacitor hold the mid-rail steady enough to work against.

Crossover distortion

The MOSFETs sit inside the op-amp's feedback loop. That is what suppresses crossover distortion, the dead zone where neither device conducts. Feedback forces the op-amp to swing hard through that region to keep the output tracking the input, so the loop conceals the nonlinearity the output stage would otherwise exhibit. A 100Ω gate resistor limits gate current and keeps the stage stable.

DebuggingThree faults the bench found and simulation did not.

  • Mismatched conversion coefficients. The resistance-to-step and step-to-resistance functions had drifted apart, using two different coefficient pairs for what should have been inverse operations. The ohmmeter returned values that were plausible and wrong, which is the worst possible failure. Resolved by establishing a single source of truth.
  • Inverted out-of-range logic. When the comparator saturates the measurement is out of range, but the two saturation cases were swapped and the boundaries were off by roughly 200Ω. Nothing in the code appeared incorrect; only bench testing against known resistors exposed it.
  • Step zero is not zero volts. The DC reference's clear routine wrote step 0 to the digipot, which maps to -5V, not 0V. It should have written step 64. I had assumed a midpoint was a minimum.

All three share a structure: the code was internally consistent and the reasoning behind it was wrong. That is precisely the class of fault simulation cannot catch, and it is the argument for building the hardware.
